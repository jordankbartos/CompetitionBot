# AI Agent Instructions

This file provides context and constraints for AI development tools working on the PokerBot project.

## Workflow Constraints

- **Git Operations:** NEVER commit or push changes automatically. Always implement and verify changes first, then request explicit user approval before performing any `git commit` or `git push` operations.
- **Documentation:** ALWAYS update relevent documentation when implementing a new feature or making any change that would make current documentation incorrect or obsolete. Use README.md or DEVELOPER.md as appropriate.

## Architecture & Deployment Constraints

0.  **Development Environment:**
    - The development environment is managed with **Conda**.
    - **Environment Name:** `slackbot`
    - **Python Version:** 3.12
    - **Verification:** Before beginning any work, verify that the `slackbot` environment exists and is currently active.

1.  **Lambda Environment:**
    - Runtime: Python 3.11 (Amazon Linux).
    - **CRITICAL:** All dependencies with C-extensions (e.g., `grpcio`, `cryptography`) **MUST** be built using the Dockerized environment in `build.sh`. Never run `pip install` directly for deployment purposes.
    - `boto3` is provided by the Lambda runtime. Do not include it in `requirements.txt` to keep the package size small.

2.  **Secret Management:**
    - Secrets (Slack tokens, Gemini API keys) are stored in AWS Secrets Manager as **Key/Value pairs**.
    - The code uses a `get_env` helper function to handle both raw strings and JSON-encoded strings from AWS. Always use this helper when accessing sensitive environment variables.

3.  **Local Testing (Docker Compose Workflow):**
    - The project uses a fully containerized local stack via `docker-compose.yml`.
    - Services: `dynamodb-local`, `db-init` (one-shot), `bridge` (Flask), and `ngrok`.
    - Secrets are managed via a `.env` file generated by `./scripts/fetch_secrets.sh`.
    - Always prefer `docker-compose up` for local E2E testing to ensure environment parity.

## Tech Stack Knowledge

- **AI:** Google Gemini (Generative AI SDK). We use `gemini-2.5-flash` for high-performance, low-cost vision and text processing.
- **Infrastructure:** Terraform. Resources are named with the prefix `poker_`.
- **Testing:** Local E2E is preferred over unit tests for vision/integration logic. Use the `ngrok` workflow documented in `DEVELOPER.md`.

## Common Tasks for Agents

- **Adding a feature:** Implement in `poker_worker/`, test via `local_bridge.py`.
- **Updating infrastructure:** Modify `main.tf`, run `./deploy.sh`.
- **Debugging Vision:** Gemini prompts are in `poker_worker/config.py`. Update the `VISION_PROMPT` to refine extraction accuracy.
